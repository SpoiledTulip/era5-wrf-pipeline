# 评测集（evals）

用来检验 skill 是否**可靠**，而不是检验智能体会不会写代码。

## 为什么需要

原有测试全部通过，却没有发现底图配色失效、国界全丢这两个缺陷——
因为测试只断言"图不是空白"，没断言"底图应该有色""国界应该有 N 条"。
**测试只保护它断言过的东西。**

`evals/` 补的是另一层：用真实场景检验 skill 的行为是否正确，
包括那些"程序跑完不报错、但结果是错的"的情况。

## 怎么用

对 `evals.json` 里每条记录：

1. 在一个干净的会话中，把 `prompt` 原样发给装好本 skill 的智能体；
2. 逐条对照 `expected_output` 里的要点，判断是否满足；
3. 记录未满足项——这些就是需要修的地方。

建议同时跑一遍**不装 skill** 的对照组。若两者表现无差别，说明这条场景
没有检验到 skill 的独特价值，应当改写或删除。

## 场景分组

| id | 名称 | 属于 | 对应问题 |
|----|------|------|---------|
| 0 | 绘图底图必须真的画出底图 | 回归 | 底图配色失效 / 边界静默缺失 |
| 1 | 国界丢失时不得静默出图 | 回归 | admin_0 无 ADM0_NAME 字段 |
| 2 | 15 km 网格的 ERA5 SST 陷阱 | 科学性 | ERA5 陆地 SST 0 K 填充 |
| 3 | 物理方案变更属科学设计级 | 边界 | C 类不得自动改 |
| 4 | CFL 报错的分类与重试纪律 | 边界 | A 类自动改 + 重试上限 |

场景 0–1 是缺陷回归评测，任何时候都应通过。
场景 2 检验科学陷阱的主动提示能力。
场景 3–4 检验自动修复的边界感——这是本 skill 与同类项目的主要差异点。

## 维护

修掉一个新缺陷时，**先写一条会失败的评测**，再改代码。
否则同样的缺陷会在别处复发。
